# Usage Guide

This guide is for teams who already know they want to use `agentest` and want the smallest reliable bootstrap path.

## Quick Start

1. run `npm i -D agentest`

2. tell your AI agent: `Use agentest to test this workflow.`

3. let the AI agent:
   - resolve `agentest/agent-kit/manifest.json`
   - inspect the repo
   - propose the first flow for review
   - wait for approval before writing files or running tests

This journey always starts with `npm i -D agentest`. If the package is missing, the guidance should say: Please run `npm i -D agentest` first. The AI should not guess pnpm, yarn, GitHub clone flows, or silent auto-install behavior.

## The Direct Manual Path

If you want to drive setup and execution by hand after installation, the current direct path is:

`npx agentest run`

## Minimal Setup

### 1. package.json

```json
{
  "type": "module",
  "scripts": {
    "test:prompts": "agentest run"
  },
  "agentest": "./agentest.config.ts"
}
```

### 2. agentest.config.ts

```ts
import { defineConfig } from 'agentest';

export default defineConfig({
  agent: {
    preset: 'claude',
  },
  tools: ['read_file', 'grep_search', 'replace_string_in_file'],
  test: {
    files: ['./tests/**/*.agentest.yaml'],
    timeoutMs: 60_000,
    failOnUnmockedTool: true,
  },
});
```

### 3. tests/fix-null.agentest.yaml

```yaml
version: 0.1
name: fixes the null-safe workflow

promptSource:
  kind: inline
  text: Fix the TypeError in user-service.ts where name may be undefined

mocks:
  - tool: read_file
    when:
      filePath: src/user-service.ts
    returns: |
      export function getDisplayName(user) {
        return user.name.trim();
      }

assert:
  tools:
    required:
      - read_file
    noUnmatchedCalls: true

  process:
    exitCode: 0
    timeout: false
```

### 4. Run

```bash
npx agentest run
```

## Generate The First Spec

The current minimal generator can create a first YAML spec from natural-language intent.

Example:

```bash
npx agentest create "Test the checkout fix workflow. The agent should search for the bug, read the broken file, apply the null-safe fix, and stop after patching."
```

Useful flags:

- `--source <ref>` to bind the generated test to a prompt file or prompt module
- `--output <path>` to control where the YAML is written
- `--run` to execute the generated spec immediately
- `--force` to overwrite an existing target file

Example with an explicit prompt module:

```bash
npx agentest create "Test the checkout fix workflow" --source src/prompts/fix-null.ts#buildPrompt --run
```

After generation, inspect the spec with:

```bash
npx agentest flow tests/checkout-fix.agentest.yaml
```

Or render Mermaid output:

```bash
npx agentest flow tests/checkout-fix.agentest.yaml --format mermaid
```

## Config Sources

`agentest run` resolves config in this order:

1. `--config <path>`
2. `agentest.config.ts`, `agentest.config.mjs`, `agentest.config.js`
3. `package.json#agentest`

`package.json#agentest` can be:

- a string path to a config file
- an inline JSON object

## Tool Declarations

There are two supported styles.

Minimal style:

```ts
tools: ['read_file', 'grep_search']
```

Detailed style:

```ts
tools: [
  {
    name: 'read_file',
    description: 'Read file contents',
    inputSchema: {
      type: 'object',
      properties: {
        filePath: { type: 'string' }
      },
      required: ['filePath']
    }
  }
]
```

Use strings first.
Only add full objects when you need more explicit MCP metadata.

## Prompt Sources

`promptSource` supports four kinds:

- `inline`: fastest way to start
- `file`: good when prompts live in `.md` or text files
- `module`: best for prompt-as-code projects
- `command`: good when prompts are generated by build steps

Examples:

```yaml
promptSource:
  kind: file
  path: ./prompts/release-note.md
```

```yaml
promptSource:
  kind: module
  ref: ./src/prompts/release-note.ts#buildPrompt
  args:
    featureName: checkout-v2
```

JavaScript and TypeScript module refs are supported.

## Test Styles

`agentest run` executes both:

- JS tests using `agentTest(...)`
- YAML prompt specs using `*.agentest.yaml`

Recommended default:

- start with YAML specs
- use JS only when you need conditional logic or custom control flow

## First Run Troubleshooting

If `npx agentest run` fails on first run, the common causes are:

### No config found

Typical fix:

- add `package.json#agentest`
- or create `agentest.config.ts`

### No tests found

Typical fix:

- create `tests/example.agentest.yaml`
- or set `test.files` in the config

### Unknown tool in a mock

Typical fix:

- add the tool name to `tools`
- for the minimal path, strings are enough

### promptSource failed to resolve

Typical fix:

- check the relative path from the spec file
- check the export name in `module#export`
- confirm the referenced file actually exists

### Agent CLI not found or not authenticated

Typical fix:

- install the target CLI
- authenticate it
- or use a custom agent command in the config
